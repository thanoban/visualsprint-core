# Implementation Brief — Participant Intelligence & Agent Accuracy

**Audience: a coding agent picking up this work with no prior context.** This is the
single entry point — read this file first, then follow the links out to the four
design documents it consolidates. Everything here has been reviewed and approved by
the project owner. Nothing described as "planned" below is implemented; everything
described as "done" is verified in code as of 2026-08-11.

## Implementation update — 2026-08-12

The code-side consolidated build is now implemented locally in two checkpoints:

- participant intelligence: identity fusion, lifecycle/ownership fixes, people API/UI,
  correction cascade, and work tracking;
- accuracy and longitudinal intelligence: temperature control, explicit abstention,
  offline multilingual evaluator and CI regression gate, deterministic person-scoped
  FSM, agents 6–10, grounding/auditing/ensemble controls, evidence-linked graphs, and

The longitudinal worker cadence is disabled by default to prevent unapproved Gemini /

explicitly synthetic multilingual scorer fixture, not a claimed model baseline. The
remaining acceptance work cannot be manufactured in code: consented human-labelled
real meetings in all language cohorts, live model evaluation/calibration, production
Supabase migration review, live platform timing/voice validation, and measured model
tier selection. The deferred shared-account identity-claims design remains out of
scope by the owner's 2026-08-11 decision.

## Non-negotiables (repeated from CLAUDE.md because they are the most commonly violated)

1. Agents interpret content; they never call each other or choose pipeline stages.
   A "pattern detected" agent output is a candidate for deterministic code to act on,
   never a trigger for another agent call.
2. Report Intelligence's input schema cannot contain raw transcript — type-enforced,
   not a prompt instruction. The same rule applies to the new Participant Narrator
   agent (§ agent roster below).
3. Verification never sees the extractor's reasoning, only the claim + raw evidence.
   Apply this pattern to every new critic agent (Claim Auditor).
4. Every external dependency goes through a swap-point interface in
   `backend/app/interfaces/`. Never call a vendor SDK directly from pipeline/agent code.
5. `proposed_action` cannot execute without an approval record — DB CHECK constraint,
   not app logic. Any new automation (pre-meeting briefs, nudges) routes through the
   existing `ProposedAction` + approval flow. Nothing new auto-sends anything.
6. Capture gaps are data, not silence. Every new metric or graph must render its own
   gaps (coverage holes, low-confidence attribution) rather than silently omitting
   them or rendering them as zero.
7. New DB tables/columns → SQLAlchemy model in `app/db/models.py` + Alembic
   **autogenerated** migration. Never hand-write SQL migrations.
8. Git: commit and push as the user. **Never add a Claude/AI co-author trailer or
   "Generated with Claude Code" footer.** No exceptions.

## The two highest-priority fixes — do these before adding any new agent

From docs/11, and worth restating because they're easy to skip past in favor of
building new features:

### Fix 1 — sampling is uncontrolled (small, do first)

`app/adapters/llm_gemini_vertex.py` builds `GenerateContentConfig` with no
`temperature`. `LlmClient.complete_structured` (`app/interfaces/llm.py`) has no
temperature parameter at all. Every extraction/verification/memory call runs at the
model's default (~1.0), which means **the same meeting processed twice can produce
different knowledge items** — a direct contradiction of this product's own
auditability claim, and a real bug given the pipeline is designed to be re-run after a
crash.

**Fix:** add `temperature: float = 0.0` to the `LlmClient` Protocol and thread it
through every adapter (`llm_gemini_vertex.py`, `llm_vertex.py`, `llm_foundry.py`).
Default 0 for every agent that extracts, verifies, classifies, or judges. Reserve
nonzero only for the future Participant Narrator's prose generation (0.2–0.3), with a
comment explaining why it's the exception.

### Fix 2 — no agent accuracy evaluation exists (do second, before any new agent)

`app/evaluation/` contains only `asr_eval.py`. There is no golden set, no
precision/recall, no regression gate for agent output — `Confidence.VERIFIED` is
currently an assertion with no evidence it correlates with being correct.

**Fix:** build `app/evaluation/agent_eval.py` mirroring `asr_eval.py`'s structure:
- A frozen, human-labelled corpus of real meetings — **must include
  Sinhala/Tamil/code-switched meetings**, not English-only, and report their metrics
  separately rather than folded into an aggregate (an aggregate hides exactly the
  weakness that matters for this product).
- Per-agent metrics: extraction precision/recall/F1 by `KnowledgeType`; ownership
  attribution accuracy with false-attribution rate tracked separately from misses;
  verification/confidence calibration.
- A CI regression gate, same shape as the ASR frozen-report gate.

Every accuracy technique in docs/11 (§ Accuracy engineering, items C–J) is
unfalsifiable without this. Build it before the Pattern Analyst, Progress Assessor, or
any other new agent — otherwise there is no way to know if they work.

## Conventions checklist (apply to every new file)

- New DB tables/columns: SQLAlchemy model in `app/db/models.py`, then
  `alembic revision --autogenerate -m "..."` — never hand-write SQL. Requires local
  Postgres up (`cd infra && docker compose up -d db`) and `alembic upgrade head` run
  first so autogenerate diffs against the real current schema.
- New vendor integration: `Protocol` in `app/interfaces/`, concrete adapter in
  `app/adapters/`, lazy-imported (vendor SDK imported inside functions, never at
  module top level — the lean `api` Docker image doesn't have ML dependencies
  installed, and a top-level import there is a repeat of a bug already found and
  fixed this session in three other adapters).
- New pipeline stage: add to `STAGES` dict in `app/orchestrator/pipeline.py`, add a
  `CaptureState` enum value (no migration needed — `Enum(native_enum=False)` emits
  plain VARCHAR), write the handler as idempotent (safe to re-run after a crash —
  delete-then-insert keyed on `capture_session_id`, matching every existing stage).
- New agent: lives in `app/agents/`, takes `(db, capture_session_id, llm: LlmClient, model: str | None = None)`,
  returns structured output via `llm.complete_structured(schema=...)`, never calls
  another agent, never decides the next pipeline stage.
- Tests: fake the vendor/LLM client via the existing injection seams
  (`worker._diarizer`, `worker._llm_client`, etc. — `monkeypatch.setattr`), never hit
  a real vendor in the test suite. Run
  `cd backend && .venv/Scripts/python.exe -m pytest tests/ -q --deselect tests/test_vector_search_postgres.py`
  after every change.
- Frontend: no charting library exists and none should be added for anything a
  hand-rolled bar/grid/polyline covers (see Group 5) — matches the existing
  inline-styled-div idiom in `frontend/app/meetings/[id]/report/page.tsx`. New pages
  use `useAuth().authedFetch`, not bare `fetch` (two existing pages — report and
  correct — incorrectly use bare `fetch` with no auth header; don't copy that).

## What NOT to do

- Do not build a bot that joins meetings without the host's explicit recording
  permission, on any platform, for any reason — this was explicitly ruled out earlier
  in this project's history as both a legal and platform-ToS violation, not a
  technical limitation to route around.
- Do not add a per-person performance score of any kind. Replaced by the interaction
  map (docs/10) by explicit decision — talk-time-as-contribution would systematically
  penalize speakers the ASR handles worse, a real bias in a Sinhala/Tamil/English
  product.
- Do not let an agent invent a pattern/repetition finding. It may only downgrade a
  deterministically-detected candidate.
- Do not merge two `Person` records, or resolve an owner, on a name match alone when
  ambiguous — return no match rather than guess.
- Do not add a charting library for anything covered by a hand-rolled bar/grid/line.
- Do not skip the golden set and ship a new agent "temporarily" without eval coverage
  — Group 0 exists specifically to prevent this exact shortcut.
